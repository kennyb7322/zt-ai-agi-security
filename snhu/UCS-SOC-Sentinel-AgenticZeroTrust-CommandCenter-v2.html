AUTONOMOUS AGENT FLEET

9 AGENTS · M365 + FOUNDRY

A fleet of purpose-built security agents orchestrated through Microsoft Foundry, grounded by Copilot for Security, and wired into Sentinel, Purview, Entra ID, and Defender. Each agent runs least-privilege, is itself a zero-trust principal, and every action is logged to an immutable audit ledger. Click an agent for its full operating spec.

FOUNDRY ORCHESTRATION PLANE

AGENT SERVICE · MCP · GROUNDING

Microsoft Foundry Agent Service is the control plane: it hosts the agents, manages their tools via the Model Context Protocol, grounds responses against your tenant's knowledge, and enforces content + identity guardrails. Copilot for Security supplies the security-domain reasoning skills.

AUTO-DEPLOY ENGINE

IaC · POWERSHELL · CI/CD

The platform deploys itself. Analytics rules, automation playbooks, agent definitions, and guardrail policies all ship as version-controlled Infrastructure-as-Code, promoted through a gated CI/CD pipeline. Below are representative artifacts the engine emits — illustrative, for review before you run anything in your own tenant.

deploy-sentinel-soc.ps1PowerShell
# UCS Agentic Zero-Trust SOC — illustrative bootstrap
param(
  [string]$ResourceGroup = "rg-soc-prod",
  [string]$Workspace     = "law-sentinel-soc",
  [string]$Location      = "eastus2"
)

# 1. Enable Sentinel on the workspace
New-AzOperationalInsightsWorkspace `
  -ResourceGroupName $ResourceGroup `
  -Name $Workspace -Location $Location -Sku "PerGB2018"
Set-AzSentinel -ResourceGroupName $ResourceGroup `
  -WorkspaceName $Workspace -Enable

# 2. Connect first-party data connectors
$connectors = "AzureActiveDirectory","MicrosoftThreatProtection",
  "Office365","AzureActivity","MicrosoftPurview"
foreach ($c in $connectors) {
  Enable-AzSentinelDataConnector -Workspace $Workspace -Kind $c
}

# 3. Register the Foundry agent identities (managed)
Deploy-UcsAgentFleet -Workspace $Workspace `
  -LeastPrivilege -ZeroStandingAccess
Write-Host "SOC baseline deployed. Review before enabling auto-action." -Fore Green
isolate-host.playbook.jsonLogic App
// Auto-containment runbook — agent-invoked
{
  "trigger": "Sentinel.Incident.HighSeverity",
  "guardrail": {
    "requireApproval": "if blastRadius > tier2",
    "maxScope": "single-host"
  },
  "actions": [
    { "defender": "Isolate-Machine" },
    { "entra": "Revoke-UserSessions" },
    { "purview": "Quarantine-SensitiveLabel" },
    { "copilot": "Draft-IncidentSummary" }
  ],
  "audit": "immutable-ledger://soc/actions"
}
agent-fleet.bicepBicep / IaC

PLUGIN & SaaS DELIVERY

FORWARD-LOOKING PRODUCTIZATION

Built so the same engine runs three ways: embedded as a Sentinel/Copilot plugin in a customer's own tenant, delivered as a multi-tenant SaaS control plane, or shipped as an MSSP white-label. Integrations below extend it into the wider security ecosystem.

Plugin

In-Tenant / BYO-Sentinel

Drops into an existing Sentinel + Copilot for Security deployment. Customer keeps full data residency.

  • Native Sentinel content pack
  • Copilot for Security plugin manifest
  • Foundry agent definitions (Bicep)
  • Runs in customer subscription
  • Zero data egress
FLAGSHIP

SaaS

Multi-Tenant / managed plane

UCS-hosted control plane orchestrating agents across customer tenants via delegated, least-privilege access (Lighthouse).

  • Cross-tenant agent fleet
  • Pooled threat intelligence
  • Per-tenant isolation & RBAC
  • Usage-metered billing
  • Continuous model & rule updates

MSSP

White-Label / partner

Rebrandable for managed security providers running many client SOCs from one pane of glass.

  • Multi-client roll-up dashboard
  • Custom branding & theming
  • Tiered SLA automation
  • Partner API & webhooks
  • Chargeback reporting
